## 2. Issues Identified
- **Flat array model** — `ScenarioStep[]` has no inherent tree/hierarchy for call nesting; `callStack` is a parallel structure bolted on
- **All-or-nothing population** — no concept of partial data (e.g., "I know the call graph but not variable values yet")
- **No provenance** — can't distinguish what came from clangd vs AI vs human
- **Variable state is a snapshot** — `Record<string, unknown>` with no timeline or delta tracking
- **Not agent-friendly** — the structure was designed for the AI tracer to produce in one pass, not for incremental multi-tool population

## 3. Plan
- Research and design 5 distinct data structure approaches, each with a different core insight
- Provide full TypeScript interfaces, concrete JSON examples, and pros/cons for each
- Include a comparison matrix across the key criteria
- Recommend the best approach with implementation path
- Approaches chosen:
  1. **Layered Frame Model** — debugger-native with layers for structure vs annotation
  2. **Event Log with Materialized Views** — event-sourced append-only log
  3. **Annotated Call Tree** — hierarchical tree mirroring the call graph
  4. **Notebook-Style Cells** — LLM-friendly chunked format
  5. **Graph-of-Snapshots** — navigable graph with full state at each node
